# Диагностика типовых проблем

## Красный индикатор «Сервер недоступен (Offline)»

Приложение стучится по адресу, определяемому из `SERVER_IP` (см.
[network-setup.md](network-setup.md)). Красная плашка = ping не проходит.

Порядок проверки:

1. **Сервер запущен?** В корне проекта: `./gradlew :server:run` — в логе должна быть строка про
   Netty на `:8080`.
2. **Сервер отвечает локально?** В браузере на том же компьютере: `http://localhost:8080/api/ping`
   → `pong`. Если нет — проблема в сервере.
3. **Правильный адрес для клиента?**
   - Android-эмулятор: адрес хоста — `10.0.2.2`, `SERVER_IP` **не задавать**.
   - iOS-симулятор: адрес — `127.0.0.1`, `SERVER_IP` **не задавать**.
   - Реальный телефон: задать `SERVER_IP = <IP компьютера в Wi-Fi>`, пересобрать.
4. **Оба устройства в одной Wi-Fi?** С телефона откройте в браузере
   `http://<IP-компьютера>:8080/api/ping` — если браузер не отвечает, проблема не в приложении.
5. **Firewall на компьютере?** macOS-firewall может блокировать входящие соединения на порт 8080
   — временно отключить и повторить проверку.
6. **На iOS реальном:** при первом запуске появляется системный диалог «разрешить локальную сеть» —
   если случайно нажали «Не разрешать», доступ нужно вернуть через Настройки → Приложение → Local
   Network.

## Задачи не появляются в списке

- Свежая установка на новом устройстве: pull-to-refresh на списке — приложение подтянет `GET
  /api/tasks`.
- Индикатор «Offline»? Значит показан локальный (возможно, пустой) снимок. Сначала чините связь
  (см. выше), затем refresh.
- Сервер только что перезапустили? Задачи из памяти сервера потеряны — это ожидаемо
  ([known-issues.md](known-issues.md)).

## Задачи есть, но правки не сохраняются

- Проверить индикатор. Красный → правки уходят в никуда, потому что связи с сервером нет.
- Проверить, что вы отсылаете **все** поля задачи, а не только изменённые: сервер полностью
  заменяет запись содержимым POST'а ([tasks.md](tasks.md#редактирование)).
- Проверить, что `id` в теле POST совпадает с id задачи, которую редактируете. Если `id = 0` —
  сервер вставит **новую** запись, а не обновит существующую.

## Приложение не собирается под Аврору

- Забыли `-PbuildVariant=aurora`? Без флага активна upstream-версия Compose, aurora-модули не
  видны.
- Собираете вместе с Android/iOS? Нельзя — свойство глобальное, гоняйте два отдельных Gradle-запуска
  ([installation.md](installation.md#аврора--rpm)).
- Aurora SDK не установлен? Компиляция `compileKotlinLinuxX64` работает без SDK, а сборка RPM
  (`buildReleasePipeline`) — уже нет: она гоняет упаковщик в Docker.

## Не работает `Modal Bottom Sheet` на Авроре

Это [известное ограничение](known-issues.md#modal-bottom-sheet-не-работает) форка Compose. В самом
приложении CTT bottom-sheet заменён на выпадающий список.
