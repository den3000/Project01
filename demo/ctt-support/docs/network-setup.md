# Настройка сети

Приложение и сервер обычно живут на разных «машинах» (эмулятор и хост, устройство и ноутбук).
CTT сам угадывает адрес сервера в типовых случаях и позволяет задать его вручную для нетиповых.

## Что и куда стучится по умолчанию

Клиент читает сгенерированную константу `AppConfig.SERVER_IP` (её собирает таска
`generateAppConfig` при сборке из `local.properties`) и выбирает адрес по правилам:

| Условие `SERVER_IP` | Android | iOS |
|---|---|---|
| пусто, отсутствует или `192.168.X.X` (плейсхолдер) | `http://10.0.2.2:8080` (адрес хоста из эмулятора) | `http://127.0.0.1:8080` (localhost симулятора) |
| задано (например `192.168.0.11`) | `http://192.168.0.11:8080` | `http://192.168.0.11:8080` |

Класс `NetworkMonitor` в этом же режиме определяет цвет индикатора «Online/Offline» — если ping не
проходит, плашка красная.

## Как задать SERVER_IP вручную (для реальных устройств)

Оба устройства (телефон и ноутбук с сервером) должны быть в **одной Wi-Fi сети**.

1. Узнать IP компьютера:
   - **Быстро на macOS:** зажмите **Option** и кликните по иконке Wi-Fi в верхней строке меню —
     появится строка «IP-адрес».
   - **Через терминал:** `ipconfig getifaddr en0` (или `ifconfig | grep "inet " | grep -v 127.0.0.1`).
2. В файле `local.properties` в корне проекта добавить строку:
   ```properties
   SERVER_IP=192.168.0.11
   ```
3. Пересобрать и запустить приложение.

Разово (без правки файла) можно передать IP флагом Gradle:

```bash
./gradlew installDebug -PSERVER_IP=192.168.0.11
```

## Аврора: `AURORA_DEVICE_IP` — это про деплой, не про клиента

Не путайте с `SERVER_IP`. `AURORA_DEVICE_IP` задаётся в `local.properties` **только** для доставки
собранного RPM на устройство по SSH (плагин `aurora-devices`, таска `runReleaseOnDevice`). Само
приложение по этой переменной сервер не ищет — оно, как и Android/iOS, читает `SERVER_IP`.

## Разрешения на HTTP

Уже настроены в проекте:

- **Android:** `AndroidManifest.xml` содержит `android:usesCleartextTraffic="true"`.
- **iOS:** `Info.plist` содержит `NSAppTransportSecurity → NSAllowsArbitraryLoads` и
  `NSLocalNetworkUsageDescription`. При первом запуске на реальном iPhone появится системный диалог
  «разрешить доступ к устройствам в локальной сети» — нужно нажать **Разрешить**, иначе соединение
  не пройдёт.

## Диагностика

- В браузере на компьютере, где запущен сервер: `http://localhost:8080/api/ping` → `pong`.
- С Android-эмулятора: `http://10.0.2.2:8080/api/ping` (можно проверить в самом приложении по
  индикатору «Online»).
- С реального устройства: `http://<IP-компьютера>:8080/api/ping` — если не отвечает, проблема почти
  всегда в firewall/Wi-Fi, а не в приложении. См. [troubleshooting.md](troubleshooting.md).
