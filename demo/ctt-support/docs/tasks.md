# Задачи

## Создание задачи

Тап по кнопке «+», ввести заголовок, при желании — описание, выбрать приоритет.
Клиент шлёт `POST /api/tasks` с `id = 0`; сервер назначает следующий свободный id и возвращает
готовую запись.

## Редактирование

Тап по карточке задачи открывает экран редактирования. Изменения (заголовок, описание, приоритет,
«выполнено») отправляются тем же эндпоинтом `POST /api/tasks` — **с уже известным id**. Сервер
находит запись по id, удаляет старую версию и вставляет обновлённую. Отдельного PUT-эндпоинта нет.

Если вы делаете это вручную (например, из `curl`), тело должно содержать **все** поля задачи, а не
только изменяемые: сервер полностью заменяет запись содержимым POST'а.

```bash
curl -X POST http://localhost:8080/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"id":42,"title":"Новый заголовок","description":"","isCompleted":false,"priority":"HIGH"}'
```

Ответ: `201 Created` + сохранённая версия задачи.

## Удаление

Свайп по карточке или кнопка «Удалить» на экране редактирования. Клиент шлёт
`DELETE /api/tasks/{id}`. Если задачи с таким id нет — сервер отвечает `404 Not Found`.

## Отметка «выполнено»

Тап по чекбоксу в карточке. Изменение идёт всё тем же POST'ом (см. «Редактирование»).

## Приоритеты

Три уровня: **LOW**, **MEDIUM** (по умолчанию), **HIGH**. Индикатор — цветная точка в карточке.
Меняются либо через выпадающий список на экране редактирования, либо через диалог выбора приоритета
(тап по индикатору в карточке). На части устройств диалог заменён на выпадающий список — см.
[known-issues.md](known-issues.md).

## Синхронизация

Клиент подтягивает актуальный список задач `GET /api/tasks` при каждом входе на экран списка. Между
устройствами (в одной сети) изменения видны сразу после перезагрузки списка (pull-to-refresh).

## Оффлайн

Приложение хранит локальную копию задач в Room. Индикатор «Offline» подсвечивает, что список
подгружен из локальной БД и может отставать от сервера — как только связь появится, `GET /api/tasks`
подтянет актуальную версию. Локальные правки при этом не буферизуются: их нужно повторить, когда
плашка снова станет зелёной. См. [troubleshooting.md](troubleshooting.md).
