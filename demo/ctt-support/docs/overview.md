# Corporate Task Tracker — обзор продукта

Corporate Task Tracker (CTT) — простой трекер задач на Kotlin Multiplatform + Compose Multiplatform.
Один и тот же экран собирается под **Android**, **iOS** и **ОС Аврора**; данные синхронизируются с
общим Ktor-сервером в локальной сети.

## Что умеет

- Список задач с индикатором приоритета.
- Создание, редактирование, удаление задачи.
- Отметка «выполнено».
- Тёмная тема.
- Индикатор статуса бэкенда (зелёный «Online» / красный «Offline»).
- Синхронизация с сервером: приложение поднимает список через GET /api/tasks и шлёт изменения POST'ом.

## Что не умеет (по дизайну текущей версии)

- **Нет входа/регистрации/аккаунтов.** Приложение работает без пользователей — все задачи лежат
  общим списком на сервере, доступ определяется только тем, кто дотягивается до сервера по сети.
  См. [auth-and-privacy.md](auth-and-privacy.md).
- **Нет облачного хранилища.** Данные живут в оперативной памяти сервера; перезапуск сервера обнуляет
  список задач.
- **Нет push-уведомлений.**

## Модель данных

Одна сущность — `Task`:

| Поле | Тип | Комментарий |
|------|-----|-------------|
| `id` | Int | 0 = «новая», серверный id назначается при первом POST |
| `title` | String | заголовок задачи |
| `description` | String | описание, по умолчанию пустое |
| `isCompleted` | Boolean | отметка «выполнено» |
| `priority` | LOW / MEDIUM / HIGH | приоритет, см. [tasks.md](tasks.md) |

## Платформы

- **Android** — собирается upstream-вариантом Compose (`./gradlew :androidApp:assembleDebug`).
- **iOS** — Xcode-проект `apps/iosApp` потребляет фреймворк `ComposeApp`.
- **Аврора** — отдельная сборка через `-PbuildVariant=aurora`. Android/iOS и Аврору **нельзя** собрать
  в одном запуске Gradle: свойство `buildVariant` глобально переключает Compose-плагин на форк.
  Подробнее — [installation.md](installation.md).

## Сервер

Ktor + Netty, слушает `0.0.0.0:8080`. Задачи хранятся в `MutableList<Task>` в памяти процесса.
Эндпоинты — `GET /`, `GET /api/ping`, `GET /api/tasks`, `POST /api/tasks`, `DELETE /api/tasks/{id}`.
Отдельного `PUT` **нет** — обновление сделано через POST с уже известным id
([tasks.md](tasks.md), [known-issues.md](known-issues.md)).
